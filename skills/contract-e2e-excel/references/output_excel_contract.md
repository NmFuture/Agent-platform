# 合同 PDF E2E 输出约定

## 最终交付

最终交付必须是一个 `.xlsx` 文件，不要只交付 JSON、CSV 或聊天摘要。中间 JSON 可保留在 `outputs/` 目录用于复核。

## Sheet 结构

1. `类型1-字段直接提取`
   - `序号`
   - `分解对象`
   - `适用项目类型`
   - `一级分类`
   - `二级分类`
   - `字段名称`
   - `抽取结果`
   - `状态`
   - `置信度`
   - `原文依据`
   - `原文位置`
   - `提取规则`

2. `类型2-付款条件提取`
   - `款项类型`
   - `款项金额（元）`
   - `款项比例`
   - `付款条件（摘录原文）`
   - `原文位置`
   - `状态`
   - `置信度`

3. `类型3-违约条款`
   - `序号`
   - `违约赔偿金种类`
   - `计违约金的合同承诺`
   - `违约赔偿金计算`
   - `分项上限及免责`
   - `原文位置`
   - `状态`

4. `类型4-合同风险识别`
   - `序号`

   - `序号`

   - `合同原文`

   - `状态`
   - `置信度`

## 状态语义

- `found`: 找到可引用的合同原文，且可输出结果。
- `not_found`: 没有找到足够证据。不要硬猜。
- `ambiguous`: 找到线索但合同填写不完整、候选项冲突或需要人工确认。
- `not_applicable`: 规则因项目类型或适用条件不适用。

## 证据要求

每个 `found` 或 `ambiguous` 单元格尽量保留：

- 原文摘录：足以让人定位判断依据。
- 原文位置：至少页码，如 `PDF第24页`。
- 置信度：自动抽取的相对可信程度，不要写成“准确率”。

## 复核口径

交付时报告：

- Excel 绝对路径。
- 5 个 sheet 是否存在。
- 类型1的 `found/not_found/ambiguous/not_applicable` 统计。
- 类型2-5各自抽到多少行。
- 明确说明未命中项仍需人工复核，不要把自动抽取包装成最终法律结论。
